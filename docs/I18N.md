# Languages (i18n)

The site ships in **English (`en`, default)**, **Russian (`ru`)**, **Georgian (`ka`)** and **Latvian (`lv`)**.
Every page, every string, every alt text, every piece of structured data and every OG image exists in all four.
There is no runtime translation and no fallback that ships: `npm run build:verify` fails if anything is missing.

Terminology, voice, names and typography for translators: [I18N-GLOSSARY.md](I18N-GLOSSARY.md).

## URLs

| Language | Home | A page |
| --- | --- | --- |
| English | `/` | `/destinations/kazbegi` |
| Russian | `/ru` | `/ru/destinations/kazbegi` |
| Georgian | `/ka` | `/ka/destinations/kazbegi` |
| Latvian | `/lv` | `/lv/destinations/kazbegi` |

Slugs are the same in every language. English keeps its existing URLs (no prefix). Private pages (`/studio`,
`/trip/*`) are localized too and stay `noindex` in every language. Each language has its own `404.html`, OG images
(`/og/<lang>/<slug>.png`) and guides feed (`/<lang>/rss.xml`). `llms.txt` / `llms-full.txt` stay English and link to
the other languages.

## Where things live

| Path | What |
| --- | --- |
| `src/i18n/config.ts` | The locale list, labels, BCP 47 tags, OG locales. Add a language here first. |
| `src/i18n/en/*.ts` | **English dictionaries, the source of truth.** Namespaces: `common` (chrome, shared components, units, place names), `pages` (page meta + page copy), `data` (words for `src/data/*`), `schema` (JSON-LD, OG), `builder` (trip builder), `studio` (itinerary studio + dashboard). |
| `src/i18n/{ru,ka,lv}/*.ts` | Translations. Each file is typed `Dict['<namespace>']`, so TypeScript rejects a missing or extra key. |
| `src/i18n/dictionaries.ts` | `Dict` type (`typeof en`) and the locale → dictionary map. |
| `src/i18n/index.ts` | Server helpers: `getLang`, `useT`, `currentPath`, plus everything from `utils.ts`. |
| `src/i18n/utils.ts` | Pure helpers safe in client code: `l`, `stripLang`, `alternates`, `langPaths`, `fmt`, `plural`, `listFormat`, `formatDate`, `formatNumber`, `localizeHtml`. |
| `src/i18n/content.ts` | `getLocalized(collection, lang)` and `slugs(collection)` for content collections. |
| `src/content/<collection>/<lang>/<slug>.md` | Content. English is the structural source (ids, order, coordinates, dates, maps, photos, cross-links are always taken from `en/`); translations only supply words. |
| `src/pages/[...lang]/` | Every page. `lang` is `undefined` for English, `ru`/`ka`/`lv` otherwise. |
| `src/components/LangSwitch.astro` | The header language switcher (works without JS). |
| `src/components/Localized.astro` | Wrap rendered Markdown (`<Localized><Content /></Localized>`) so internal links get the language prefix. |

## The rules (for every feature)

1. **No hard-coded user-visible text.** Headings, buttons, labels, `alt`, `aria-label`, `title`, `placeholder`,
   visually hidden text, SVG `<text>`, `<title>`/description props, JSON-LD names, error messages, `alert()`s,
   the text of a WhatsApp/email hand-off: all of it comes from a dictionary. Only ids, URLs, CSS, clock times and
   brand names (Voyage Georgia Rezo, Mercedes Sprinter, Mitsubishi Delica, WhatsApp) may be literals.
2. **Add the English key first**, in the namespace that matches where it shows, with a short comment saying where.
   Then add the same key to `ru`, `ka` and `lv` in the same change. `npx tsc --noEmit` fails until all four have it.
   Never ship an English string in a translation file as a placeholder.
3. **Paths in code are always language-neutral** (`'/destinations'`). Localize at the point of output:
   `href={l(lang, '/destinations')}`. Pass neutral paths to `Base` (`path`), `PageIntro`/`Breadcrumbs` (`crumbs`)
   and `src/lib/schema.ts` builders (with `lang`); they localize themselves. For trusted HTML strings from a
   dictionary use `set:html={localizeHtml(lang, t.pages.x.bodyHtml)}` and write links unprefixed inside them.
4. **Structure stays out of dictionaries.** ids, coordinates, scores, prices, order and flags live in `src/data/*` or
   front matter; dictionaries are keyed by those ids (see `data/faqs.ts` + `data.faqs`, `data/vehicles.ts` +
   `data.vehicles`). A translation must never be able to change structure.
5. **Counts, lists, numbers, dates are formatted, not concatenated.** `plural(lang, n, t.common.units.days)` (each
   language gives its own CLDR forms: ru `one/few/many/other`, lv `zero/one/other`, ka `one/other`),
   `listFormat(lang, items)`, `formatNumber`, `formatDate`. Interpolate with `fmt(template, { name })`; never build a
   sentence from fragments, because word order differs by language.
6. **Islands and client scripts don't import dictionaries.** Pass the namespace they need as a prop
   (`t={t.builder}`, `lang={lang}`) or render strings into the HTML (`data-*` / a JSON `data-i18n` attribute, as
   `World.astro` does for `src/scripts/home-world.ts`). Import helpers from `src/i18n/utils`, types with `import type`.
7. **Place names** shown on maps or in routes go through `t.common.places[englishName]`; add the name there in all
   four languages if it's new.
8. **Layouts must survive longer words.** Russian and Latvian run ~20–30 % longer than English; Georgian is tall
   and has no capitals (`:lang(ka)` resets negative letter-spacing). Don't fix widths to English copy, and check a
   new screen in `ru` and `ka` at phone width.

## Recipes

**A new page** — create `src/pages/[...lang]/my-page.astro`:

```astro
---
import Base from '../../layouts/Base.astro';
import { getLang, l, langPaths, useT } from '../../i18n';
export const getStaticPaths = () => langPaths();
const lang = getLang(Astro);
const t = useT(lang);
const c = t.pages.myPage; // add `myPage` to src/i18n/{en,ru,ka,lv}/pages.ts
---
<Base title={c.title} description={c.description} path="/my-page">
  <h1>{c.heading}</h1>
  <a href={l(lang, '/contact')}>{t.common.footer.contact}</a>
</Base>
```

If it is indexable, add it to `corePageList` in `src/data/pages.ts` and its `meta` entry in every `pages.ts`;
the sitemap (with hreflang), llms.txt and OG images follow automatically.

**A dynamic page** — combine languages with your own params:

```ts
export async function getStaticPaths() {
  const all = await slugs('guides');
  return locales.flatMap((lang) => all.map((slug) => ({ params: { lang: lang === defaultLocale ? undefined : lang, slug } })));
}
const entry = (await getLocalized('guides', getLang(Astro))).find((e) => e.slug === Astro.params.slug)!;
```

Use `entry.slug` (language-neutral) in URLs, never `entry.id` (which is `ru/<slug>`).

**New content** — add `src/content/<collection>/en/<slug>.md`, then the same file name under `ru/`, `ka/` and
`lv/`. Translate only words; structural front-matter fields are ignored in translations and taken from English
(see `STRUCTURE` in `src/i18n/content.ts`). Keep link targets unprefixed (`(/destinations/tbilisi)`).

**A new language** — add it to `locales`, `localeMeta` and `intlLocale` in `src/i18n/config.ts`; create
`src/i18n/<code>/` (copy the shape of `en/`, typed `Dict[...]`) and register it in `src/i18n/dictionaries.ts`;
add `src/content/*/<code>/`; add the code to `LOCALES` in `scripts/verify-seo.mjs`; add its private paths to
`public/_headers`; add font coverage in `src/styles/fonts.css` and `src/lib/og.ts` if it needs a new script.

## Checks

- `npx tsc --noEmit` — every dictionary matches the English shape.
- `npm run build:verify` — every page exists in every language with the right `<html lang>`, reciprocal hreflang +
  `x-default`, a localized canonical, no page whose main text is identical to English, every content file
  translated, and no dictionary still pointing at English.
- Translations here were drafted with AI assistance and should be reviewed by native speakers before launch
  (see docs/LAUNCH-CHECKLIST.md).
